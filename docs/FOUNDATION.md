# Foundation milestone

Product name: **agentVIEW** (user-selected). Visual direction takes inspiration
from [Appwrite](https://appwrite.io/): dark surfaces, restrained pink accents,
compact navigation and clear panel boundaries. No third-party UI code or assets
were copied. The original icon is generated by `scripts/make-icon.py` with fixed
sampling and stored DEFLATE; SVG and PNG can be checked byte-for-byte.

The workspace shows clear Claude/Codex intake → project coordinator → subagent views.
No live providers are connected in this milestone.

## Implementation boundary

- Keep allow-listed document browsing in a separate `viewer://localhost` window,
  with its GET-only router and no workspace capabilities.
- The new `workspace://localhost` window serves only embedded HTML/CSS/JS.
  Narrow Tauri commands read snapshots, enqueue user messages, change simulated
  availability, dispatch synthetic replies, and open the existing viewer.
  Commands check the trusted window label and exact workspace origin as well as
  Tauri's explicit capability list. They accept no filesystem paths or shell code.
- SQLite stores only app-owned demo records under the app data directory. Use
  transactions, schema versions, foreign keys, request deduplication, bounded
  history pages and atomic synthetic delivery/reply. Never hold a database lock
  while running external code. No provider code runs in this slice.
- Two intake roots represent Claude and Codex. Coordinators belong to an intake;
  subagents belong to a coordinator and inherit its provider/project. Tree view
  shows reporting lines; project view groups the same records across providers.
  Explicit demo labels prevent confusing sample agents with running sessions.
- The UI shows saved/queued/delivered messages, agent availability and ancestry.
  Busy/paused agents keep messages queued until resumed idle. Synthetic replies
  are derived from stored messages and commit with delivery, so retry/restart
  cannot create a second reply. App-owned local demo writes follow explicit UI
  actions; document access remains read-only.
- The token-usage view groups agents by their provider and shows input, output,
  cached input and total columns. All real telemetry is unavailable in this
  milestone; the simulator makes no provider requests. Do not infer tokens from
  text length or subscription usage. Later adapters must supply separate measured
  receipts, source/freshness and provider-specific usage windows.
- The next live slice will wrap multiple Claude Code sessions launched in their
  own project directories. Existing Zellij sessions remain independent; attaching
  to an already running session requires a separate compatibility check.

## Results

The original Python hardlink failure was reproduced before the fix. Both helpers
now reject hardlinks; three regression/control cases bring Python to 60 passing
tests. `foundation_refuter` independently reran the five read tests, saw both
hardlink regressions fail the old revision, and checked test/build failure
propagation in `scripts/check-rust.sh`. Official Nix action pin verification was
performed by worker `foundation_fixes`; hosted GitHub CI was not run here.

Root verification with the unchanged nixpkgs lock, cargo 1.99.0 and rustc 1.99.1:

- `scripts/check-foundation.sh` runs Python, Rust library tests (23 existing core
  tests and 8 new workspace tests), normal desktop compilation, icon verification,
  original viewer GUI policy checks, and two-process workspace GUI restart checks.
  It restores the normal debug build at the end and saves full logs under `/tmp`.
- New backend tests cover both provider trees, invalid parentage, idempotency and
  conflicting retries, busy/pause, concurrent initial opens, concurrent delivery,
  stable history pages, malformed payloads, future schema preservation and database
  symlink refusal. SQLite is newly bundled by locked rusqlite/libsqlite3-sys;
  added crate license texts are in `licenses/workspace-crates.txt`.
- Real WebKitGTK/Xvfb probes exercise hierarchy/project/filter views, usage's
  unavailable state, composer, hostile text escaping, restart, resume, one reply
  per message, and rejection of all five workspace commands from the docs window.
- Root refuter found stale queued labels in loaded older pages. Refresh now
  reloads each loaded page (up to 1000 rows). A GUI regression creates 105 queued
  requests, loads older history and verifies a delivered old bubble updates.
  Refuter rechecked this correction and found no remaining material objection.
- A suspected missing test hook was withdrawn after following the existing e2e
  delegation. A real setup issue was corrected after reading pinned Tauri source:
  registered custom schemes are classified local, so the workspace capability
  uses `local:true`, scoped to the workspace label; native exact URL checks remain.
- GUI runners use isolated directories and private X displays. A normal build
  cannot serve test endpoints; all GUI hooks require the existing release-forbidden
  `e2e` feature. Release-string checks now include new data/test overrides.

Final run logs and preview: `/tmp/agentview-foundation-final/` (local evidence,
not a checked-in artifact). Python's existing cleanup warnings remain despite
passing tests; Xvfb emits Mesa/DRI3 warnings. No live providers, paid APIs,
dependency advisory recheck, release binary, AppImage rebuild, FUSE, Wayland or
multi-machine test is claimed. Usage counters remain explicitly unavailable.
